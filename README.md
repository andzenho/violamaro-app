# Виола Маро

Next.js 15 (App Router, TypeScript) + Supabase.

## Запуск локально

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Скопируйте `.env.example` в `.env.local` и заполните переменные:

   ```bash
   cp .env.example .env.local
   ```

3. Запустите dev-сервер:

   ```bash
   npm run dev
   ```

   Приложение откроется на [http://localhost:3000](http://localhost:3000).
   Проверить подключение к базе можно на [http://localhost:3000/api/health](http://localhost:3000/api/health).

## Переменные окружения

| Переменная                  | Где взять                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`   | Supabase Dashboard → выбранный проект → Project Settings → Data API → Project URL             |
| `SUPABASE_SERVICE_KEY`       | Supabase Dashboard → выбранный проект → Project Settings → API Keys → `service_role` секретный ключ |
| `API_SECRET`                 | Придумываете сами (любая случайная строка) — им защищены `/api/event`, `/api/status` и `/api/export` |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Ключ сервисного аккаунта Google — как получить, написано ниже                                  |
| `SHEET_ID`                   | Из адреса таблицы: `docs.google.com/spreadsheets/d/`**`<вот эта часть>`**`/edit`               |
| `CRON_SECRET`                | Придумываете сами — им Vercel Cron представляется роуту `/api/export`                          |

`SUPABASE_SERVICE_KEY` — секретный ключ с полным доступом к базе. Используется только на сервере
(в API-роутах), никогда не должен попадать в код на клиенте или в публичный репозиторий.

`API_SECRET` нужно передавать во внешний сервис (Salebot и т.п.) — он ставит его в заголовок
`X-Api-Key` при каждом запросе к нашим роутам.

`GOOGLE_SERVICE_ACCOUNT_JSON` и `SHEET_ID` нужны только выгрузке в Google-таблицу; без них
остальные роуты работают как раньше.

## Тесты

Два теста живут по адресам `/test/empat` («Эмпат ли вы») и `/test/koleso` («Колесо эмпата»).
Это готовые однофайловые страницы из `public/legacy/`, которые отдаются по этим адресам через
`rewrites` в `next.config.ts`. Вопросы, подсчёт результата и экраны в них не менялись — заменена
только обвязка: вместо Телеграма и Google Apps Script они принимают параметры из адреса
и шлют события на наш API.

### Параметры в ссылке

```
/test/empat?k=tg_12345&src=tg-bot
```

| Параметр | Что это |
| --- | --- |
| `k` | Кто проходит. Это `platform_user_id` с префиксом платформы: `tg_`, `max_` или `vk_`. Бот подставляет его в ссылку сам — отдельного запроса к нам не нужно. Может отсутствовать: тогда прохождение анонимное. |
| `src` | Метка источника. Принимаются только `tg-bot`, `max-bot`, `vk-post`, `landing`, `chat`; всё прочее игнорируется. |

Оба сохраняются в `sessionStorage` при открытии страницы, поэтому переживают перезагрузку
и переходы внутри теста.

В Salebot ссылка собирается подстановкой переменной, например `.../test/empat?k=tg_{{id}}&src=tg-bot`.

### Что тест присылает

| Момент | Событие | Что в `payload` |
| --- | --- | --- |
| Открыл первый вопрос | `test_open` | — |
| Дошёл до результата | `test_done` | **Эмпат:** `rank`, `percent`, `scales`, `forks`, `answers`, `seconds`, `fast`, `monotone`<br>**Колесо:** `otdayu`, `ostaetsya`, `zazor`, `wheel` (по сферам), `worst`, `forks`, `answers`, `seconds`, `fast`, `monotone` |
| Долистал до экрана программы | `offer_view` | — |
| Отправил анкету | `lead` | Имя, контакт, готовность, согласия (`accept_pd`, `accept_ads`, `consent_ts`) и цифры результата |

`rank` и `percent` из `test_done` отдаёт бот через `GET /api/status`.

### Анонимные прохождения

Пришедшему без `k` тест заводит собственный идентификатор вида `web_<случайная строка>`
и держит его в `localStorage`. Без этого три события одного захода легли бы в базу как три
разных человека. Если тот же человек позже откроет тест по ссылке с ключом, сервер сведёт
прежние события с опознанной записью и уберёт анонимную.

## Выгрузка в Google-таблицу

Интерфейса у системы нет: руководитель отдела продаж работает в Google-таблице. Роут
`/api/export` собирает данные из базы и полностью перезаписывает в ней два листа.

### Что в таблице

**Лист «Заявки»** — одна строка на человека, а не на заявку. Попадают только те, у кого есть
хотя бы одно событие `lead`.

| Колонка | Откуда берётся |
| --- | --- |
| Дата первой заявки | первое событие `lead` |
| Имя | `payload.name` заявки; если человек оставлял заявку дважды — первое непустое |
| Контакт | `payload.contact` заявки, по тому же правилу |
| Платформа | поле человека |
| Источник | `first_source` человека — метка самого первого касания |
| Тест | тесты, по которым приходили заявки |
| Результат | из последнего `test_done` |
| Процент | из последнего `test_done` |
| Заявок | сколько всего событий `lead` |
| Дата последней заявки | последнее событие `lead` |

**«Результат» и «Процент» значат для двух тестов разное** — тесты устроены по-разному, и общей
шкалы у них нет:

| Тест | Результат | Процент |
| --- | --- | --- |
| Эмпат ли вы | тип эмпата — «Эмпат-донор», «Эмпат без фильтра» и т. д. | процент эмпатии |
| Колесо эмпата | какие сферы проседают — «Проседает: Тело и силы, Деньги» | сколько **остаётся себе** (`ostaetsya`) |

Если заявка пришла не из формы теста, а от бота через `/api/event`, имени и контакта в `payload`
нет. Тогда подставляются поля человека — `first_name`, телефон, `@логин`, почта. Поэтому пустая
колонка «Контакт» значит ровно одно: связаться с человеком нечем.

**Лист «События»** — полный след. Строки сгруппированы по человеку, внутри группы идут по
возрастанию времени, чтобы путь читался сверху вниз; сами группы — от недавних к давним.

| Колонка | Что внутри |
| --- | --- |
| Дата и время | ДД.ММ.ГГГГ ЧЧ:ММ |
| Человек | имя, иначе `@логин`, иначе платформа и id |
| Платформа | Telegram / MAX / ВКонтакте / Сайт |
| Событие | «Клик по посту», «Прошёл тест», «Заявка» и т. д. |
| Источник | метка канала на самом событии |
| Тест | «Эмпат ли вы» / «Колесо эмпата» |
| Детали | выжимка из `payload` одной строкой |

«Детали» — не сырой JSON, а короткая сводка: `Эмпат-донор · 73% · 5 мин` для пройденного теста,
`Мария · +7 999 123-45-67 · готовность: готов сейчас` для заявки. Сырьё для калибровки (ответы,
шкалы, развилки) в таблицу не идёт. Пометки `быстро` и `однообразно` ставит сам тест — по ним
видно прокликанное прохождение, за которым результата нет.

Сортировка на обоих листах — свежие сверху.

### Оформление

Шапка закреплена и выделена, на всех колонках фильтры, ширина подобрана по содержимому.
Условное форматирование на «Заявках»: красным — строки без контакта, зелёным — заявки за
последние сутки, синим — люди, оставившие больше одной заявки. На «Событиях» подсвечена первая
строка каждого человека, чтобы блоки не слипались.

Колонка «Контакт» жёстко текстовая, и это не перестраховка: телефон с ведущим плюсом Google
Таблицы принимают за формулу и превращают ячейку в `#ERROR!` — на этом уже терялись живые
заявки. Запись идёт с `valueInputOption: RAW`, а текстовый формат колонки не даёт таблице
передумать позже.

Даты записываются числами с числовым форматом колонки, а не строками. Выглядят они как
`08.09.2026`, но сортировка и фильтр по датам при этом работают как с датами, а не как с
текстом. Время считается по Москве (`Europe/Moscow`): в базе оно лежит в UTC, и без пересчёта
заявка, оставленная в час ночи, уехала бы на предыдущий день.

Сводок, графиков и воронок в таблице нет — их руководитель считает у себя. Обратной записи тоже
нет: таблица только читается, из неё в базу не попадает ничего.

### Ключ доступа к таблице

Ходим в таблицу от **сервисного аккаунта** — у него свой почтовый адрес, и человека в этой
цепочке нет: крону некому нажимать «разрешить».

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект
   (или выберите существующий).
2. **APIs & Services → Library → Google Sheets API → Enable.**
3. **APIs & Services → Credentials → Create credentials → Service account.** Имя любое,
   роли на уровне проекта выдавать не нужно — доступ даётся самой таблицей.
4. Откройте созданный аккаунт → вкладка **Keys → Add key → Create new key → JSON.**
   Скачается файл — это и есть значение `GOOGLE_SERVICE_ACCOUNT_JSON`.
5. Скопируйте адрес аккаунта (вида `имя@проект.iam.gserviceaccount.com`) с вкладки **Details.**
6. Откройте нужную Google-таблицу → **Настройки доступа** → добавьте этот адрес
   с правами **Редактор**. Без этого шага роут получит от Google «нет доступа»:
   ключ сам по себе не открывает ничего.
7. `SHEET_ID` возьмите из адреса таблицы — часть между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`1shscjrlIPk…`**`/edit`.

Содержимое скачанного JSON кладётся в переменную целиком, одним значением. Если поле ввода
ломает переносы строк внутри `private_key` (так бывает), закодируйте файл в base64 и положите
результат — роут принимает оба вида:

```bash
base64 -w0 < service-account.json
```

### Защита от чужой таблицы

Перезапись полная и необратимая, а `SHEET_ID` легко скопировать не от той таблицы. Поэтому
перед первой записью роут смотрит, что в листах лежит. Лист считается своим, если он пуст или
если в первой строке стоит ровно наша шапка. Если в таблице найдётся что-то ещё, выгрузка
останавливается, **ничего не перезаписав**, и отвечает `409`:

```json
{ "ok": "0", "error": "в таблице есть чужие данные (Бюджет 2026) — выгрузка остановлена, …",
  "sheets": ["Бюджет 2026"] }
```

Если таблица правильная и содержимое можно затереть — вызовите роут ещё раз с `?force=1`.
Крону этот обход недоступен намеренно: расписание, молча стирающее чужую работу раз в
пятнадцать минут, — это авария, а не удобство.

Пустая таблица со стандартным листом `Лист1` не требует ничего: он переименовывается в
«Заявки», рядом заводится «События». Свои листов сверх этих двух роут не создаёт, а чужие,
если они в таблице есть, не трогает и не удаляет.

### Расписание

Крон настроен в `vercel.json`:

```json
{ "crons": [{ "path": "/api/export", "schedule": "*/15 * * * *" }] }
```

Vercel Cron умеет только `GET` и своих заголовков не ставит — `X-Api-Key` ему передать нечем.
Зато он сам шлёт `Authorization: Bearer <CRON_SECRET>`, по нему роут его и опознаёт. Поэтому
`CRON_SECRET` нужно завести в переменных окружения проекта на Vercel; ключ для людей и ключ
для расписания намеренно разные — отзыв одного не задевает другое.

**На бесплатном плане Vercel крон запускается раз в сутки** независимо от расписания: `*/15`
там просто не отработает с такой частотой. Каждые пятнадцать минут заработает после перехода
на Pro — правку в `vercel.json` для этого делать не придётся. Вручную роут доступен всегда.

## Миграции базы (Supabase CLI)

Схема (`people`, `events`, `links`) лежит в `supabase/migrations/` как обычные `.sql`-файлы.
GitHub-интеграция Supabase не подключена — миграции применяются вручную.

Накатить на реальный проект Supabase:

```bash
npx supabase login
npx supabase link --project-ref <ваш-project-ref>
npx supabase db push
```

`<ваш-project-ref>` — это часть URL проекта в Supabase Dashboard (`https://supabase.com/dashboard/project/<project-ref>`).

Добавить новую миграцию в будущем:

```bash
npx supabase migration new <название>
```

## Деплой на Vercel

1. Зайдите на [vercel.com](https://vercel.com) → Add New → Project.
2. Импортируйте этот репозиторий (`violamaro-app`).
3. В настройках проекта (Settings → Environment Variables) добавьте те же переменные,
   что и в `.env.example`: `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `API_SECRET`,
   `GOOGLE_SERVICE_ACCOUNT_JSON`, `SHEET_ID`, `CRON_SECRET`.
4. Запустите деплой. Vercel сам определит Next.js и настроит сборку.
5. После деплоя проверьте `https://<ваш-домен>/api/health`.
6. Расписание выгрузки Vercel подхватит из `vercel.json` сам; проверить его можно
   в Settings → Cron Jobs.

## Проверка API

Ниже — примеры для локального запуска (`http://localhost:3000`); на проде замените адрес
и подставьте свой `API_SECRET`.

### POST /api/event

Новый человек из Telegram-бота, открыл тест:

```bash
curl -X POST http://localhost:3000/api/event \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: <ваш API_SECRET>" \
  -d '{
    "platform": "tg",
    "platform_user_id": "12345",
    "username": "ivan_petrov",
    "first_name": "Иван",
    "type": "test_open",
    "source": "tg-bot",
    "test": "empat",
    "payload": { "utm_source": "instagram", "utm_medium": "cpc", "utm_campaign": "launch" }
  }'
# { "ok": "1", "person_id": "..." }
```

Тот же человек прошёл тест (событие допишется к уже существующей записи):

```bash
curl -X POST http://localhost:3000/api/event \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: <ваш API_SECRET>" \
  -d '{
    "platform": "tg",
    "platform_user_id": "12345",
    "type": "test_done",
    "source": "tg-bot",
    "test": "empat",
    "payload": { "rank": "Эмпат без фильтра", "percent": 73 }
  }'
# { "ok": "1", "person_id": "..." }
```

Заявка с сайта — без `platform_user_id`, склейка произойдёт по телефону/username, если человек
уже встречался в другой сети:

```bash
curl -X POST http://localhost:3000/api/event \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: <ваш API_SECRET>" \
  -d '{
    "platform": "web",
    "phone": "+7 999 123-45-67",
    "type": "lead",
    "source": "landing",
    "test": "empat"
  }'
# { "ok": "1", "person_id": "..." }
```

### POST /api/track

Роут для самого теста. Открыт без ключа — страница в браузере получить `API_SECRET` не может, —
поэтому принимает только белый список полей и сам зовёт ту же серверную функцию, что и
`/api/event`. Секрет остаётся на сервере.

```bash
curl -X POST http://localhost:3000/api/track \
  -H "Content-Type: application/json" \
  -d '{
    "type": "test_done",
    "test": "empat",
    "k": "tg_12345",
    "anon_id": "web_a1b2c3d4e5",
    "source": "tg-bot",
    "payload": { "rank": "donor", "percent": 90 }
  }'
# { "ok": "1", "person_id": "..." }
```

Допускаются только `type` из `test_open` / `test_done` / `offer_view` / `lead`, `test` из
`empat` / `koleso`, `source` из пяти меток выше; `payload` не больше 8 КБ. Всё остальное — 400.

### GET /api/status

Человек найден, тест пройден:

```bash
curl "http://localhost:3000/api/status?platform=tg&platform_user_id=12345&test=empat" \
  -H "X-Api-Key: <ваш API_SECRET>"
# { "ok": "1", "found": "1", "test_open": "1", "test_done": "1", "lead": "0", "lead_any": "0",
#   "rank": "Эмпат без фильтра", "percent": "73", "test_date": "2026-09-08" }
```

Человека нет в базе — штатный ответ, не ошибка:

```bash
curl "http://localhost:3000/api/status?platform=tg&platform_user_id=99999&test=empat" \
  -H "X-Api-Key: <ваш API_SECRET>"
# { "ok": "1", "found": "0", "test_open": "0", "test_done": "0", "lead": "0", "lead_any": "0" }
```

### POST /api/export

Собрать данные и переписать оба листа в Google-таблице:

```bash
curl -X POST http://localhost:3000/api/export \
  -H "X-Api-Key: <ваш API_SECRET>"
# { "ok": "1", "leads": "128", "events": "3417", "people": "612" }
```

В таблице оказалось что-то чужое — выгрузка остановлена, ничего не перезаписано:

```bash
curl -w "\n%{http_code}\n" -X POST http://localhost:3000/api/export \
  -H "X-Api-Key: <ваш API_SECRET>"
# { "ok": "0", "error": "в таблице есть чужие данные (Бюджет 2026) — …", "sheets": ["Бюджет 2026"] }
# 409
```

Затереть содержимое осознанно:

```bash
curl -X POST "http://localhost:3000/api/export?force=1" \
  -H "X-Api-Key: <ваш API_SECRET>"
```

Так же роут дёргает расписание — `GET` с ключом крона вместо `X-Api-Key`:

```bash
curl "http://localhost:3000/api/export" \
  -H "Authorization: Bearer <ваш CRON_SECRET>"
```

### Без API-ключа

```bash
curl -w "\n%{http_code}\n" "http://localhost:3000/api/status?platform=tg&platform_user_id=12345&test=empat"
# { "ok": "0", "error": "unauthorized" }
# 401
```
